# 项目资料目录分类重组转存

## 适用场景

用户要求把一个项目资料目录按**新的分类结构**重新组织到另一个目录，例如：

- 「把 A 目录下所有文件转存到 B 目录，并按此结构分类」
- 「按 01-立项/02-需求/03-系统设计… 重新归类整理」
- 项目资料从「按来源编号」（1.合同资料、2.系统开发需求文档…）迁移到「按生命周期阶段」

这类需求在用户的项目群（`D:\KnowsB\09-YXSVN\000项目资料2026\01透明供电` ~ `20广汽传祺` 等 20+ 个目录）上高度可复用。

## 核心纪律（不可违背）

1. **原文件只读不动** — 默认用「复制」而非「移动」，源文件必须完整保留。
2. **先 dry-run，后 apply** — 任何写操作前必须先生成完整映射清单。
3. **歧义逐条确认** — 分类归属有争议的文件组，必须列成选项让用户拍板，不得自行假设。
4. **不擅自丢弃数据** — 疑似重复的文件默认全部保留，冗余项在报告中标注，由用户决定清理。

## 工作流

### 第 1 步：扫描源目录

```bash
cd "源目录" && find . -type f -printf "%p\n" | sort
```

同时确认目标目录是否已存在、分类文件夹是否已建好。**注意检查两处是否同名目录**（用户可能已手动移动过），避免建重。

### 第 2 步：列出歧义，逐条确认

用 AskUserQuestion 确认以下 4 类高频歧义（一次最多 4 个问题）：

| # | 歧义点 | 常见选项 |
|---|---|---|
| 1 | 转存方式 | 复制（推荐，保留原件）/ 移动 |
| 2 | 大批量归属不明的文件组归哪类 | 按该类的实际语义给 3 个候选 |
| 3 | 明显属于**其它项目**的文件 | 归入「其它项目」类 / 不转存留在原处 |
| 4 | 垃圾与临时文件 | 全部排除（推荐）/ 全部转存 |

**必须排除的文件**（默认规则）：
- `.svn`、`.git` 等版本控制元数据目录
- `Thumbs.db`、`Desktop.ini`
- `~$` 开头的 Office 临时锁文件（文件未正常关闭遗留）

### 第 3 步：编写分类脚本（plan / apply 双模式）

参考模板：`D:\YXAI\_classify_huapai.py`（已实现以下全部能力，改常量与 `classify()` 即可复用）

关键设计：
- `classify(rel_path)` 函数：按**源相对路径的顶层目录名 + 文件名特征**返回目标相对路径
- 在 6 大分类下**保留来源子目录名作为二三级目录**（如 `03-系统设计/部署资料/`），既完成重组又不丢失原组织上下文
- CSV 输出用 `utf-8-sig` 编码，Excel 打开中文不乱码
- 清单记录每个文件的：状态（COPY/SKIP_DUP/RENAME/EXCLUDED）、源路径、目标路径、大小、说明

### 第 4 步：dry-run 生成清单

```bash
PYTHONIOENCODING=utf-8 python _classify_XXX.py plan
```

输出各分类落盘文件数，人工核对是否合理（某类特别多/特别少通常是分类规则写错）。

### 第 5 步：检测重复

跨目录同名文件要**按内容 hash 区分**：
- 内容相同 → 标记冗余，但**默认仍全部复制**，在报告中标注
- 内容不同 → 全部保留

### 第 6 步：apply 执行复制

```bash
PYTHONIOENCODING=utf-8 python _classify_XXX.py apply
```

### 第 7 步：校验（不可省略）

参考模板：`D:\YXAI\_verify_huapai.py`

比对「计划落盘集合」与「目标目录实际集合」，必须做到 `missing == 0 且 extra == 0` 才算通过。

### 第 8 步：交付清单

用 present_files 提供清单 CSV，让用户可按图索骥核对。

## 已踩过的坑（务必规避）

1. **`shutil.copy2` 保留源文件只读属性** → 重跑脚本覆盖已存在目标文件时抛 `Permission denied`。
   修复：覆盖前先 `os.chmod(dst, 0o666)`。
   ```python
   if dst_file.exists():
       try: os.chmod(dst_file, 0o666)
       except Exception: pass
   shutil.copy2(src_file, dst_file)
   ```

2. **扫描与执行之间存在时间差** — 源目录可能在扫描后新增文件（本次遇到：扫描后新增 63MB 的 `软件操作说明书v1.0.docx`，mtime 晚于扫描时间）。
   对策：apply 完成后，检查源目录中 mtime 晚于扫描时间的文件：
   ```bash
   find "源目录" -type f -newermt "YYYY-MM-DD HH:MM" -printf "%TY-%Tm-%Td %TH:%TM  %p\n" | sort
   ```
   有新增则补转存。**大文件（如 .mp4、大 .docx）保存耗时长，最容易踩到。**

3. **同名文件不等于重复文件** — 必须算 hash 才能判断。实测 8 组同名文件中仅 3 组内容相同。

4. **源目录可能存在冗余嵌套** — 如 `X/X/文件`，需在分类时压平一层。

5. **Windows 中文路径** — 用 `pathlib` + `PurePosixPath` 处理路径分隔符；bash 里跑 Python 时加 `PYTHONIOENCODING=utf-8` 防乱码。

6. **`os.walk` 排除目录要就地修改 `dirnames`**（切片赋值），才能在遍历阶段就跳过 `.svn`，避免元数据文件混进 `excluded` 计数。
