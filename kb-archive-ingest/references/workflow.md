# 知识库归档去重入库 —— 标准工序

适用于：把散落的 `D:\xx` 源目录，去重后整合进结构化知识库 `D:\KnowsB`（文档）与
`D:\KnowsCode`（代码/工程二进制）。本工序已跑通 4 轮（BpgYx / EMSDocuments / 02产品 /
02研发产品管理），流程稳定。

---

## ⚠️ 用户强约束（任何执行前必须守）
1. **先出清单，用户确认后再动文件**。删除/重组/覆盖类操作一律先给清单+目标路径。
2. **保留原始文件、先做副本/同盘改名**（可逆）。真正"删除释放空间"由用户手动做。
3. 沙箱 SAFE_DELETE 是 fail-closed：**永久删除走用户**；本工序只做"同盘改名隔离/入库"。

---

## Phase 0 — 明确范围与边界（先问，不猜）
- 本次要处理哪个/哪几个源目录？
- 目标：仅去重（移除已在 KB 的副本）？还是连同"独有内容入库 KB"一起做？
  （本用户当前目标是 **全面 AI 化 → 独有内容直接入库 KnowsB**。）
- 是否允许新增顶层域？本用户允许（如 `16-智慧电房`、`92-研发管理`）。

## Phase 1 — 只读普查（不碰任何文件）
- 文件数、总体积、扩展名分布、是否含 `.svn`、顶层/二级目录结构。
- 目的：判断是"冗余垃圾堆(BpgYx)"还是"以独有内容为主(02产品)"，决定后续力度。
- 用文件脚本（见 pitfalls：勿用内联 heredoc 传 Windows 路径）。

## Phase 2 — 哈希（建立跨根索引）
1. **先把 KB 全文 sha 补满**（关键前置）：
   `python hash_index.py full --root D:\KnowsB --full-all --db <db>`
2. **把源目录加入同一库**：
   `python hash_index.py build --root D:\<源> --full-all --db <db>`
   （源目录小则 `--full-all` 直接全量算，保证完整；大目录可用分层自动模式。）
3. 核查：`python hash_index.py stat --db <db>` 看各根状态。

## Phase 3 — 分类 A/B/C
- `python kb_classify.py --source-root D:\<源> --source-name <名> --kb-root D:\KnowsB --db <db> --out-dir <dir> [--other-roots "D:\BpgYx;..."]`
- 输出：
  - `<名>_A_dup_in_knowsb.csv` 内容已在 KB（可隔离移除）
  - `<名>_B_self_dup.csv`     内部自重复（保留 1 / 删余 N）
  - `<名>_C_unique.csv`       全局独有（应入库，不可删）
  - `<名>_classify_summary.json`
- **自检必过**：`A + B删 + B留 + C == 源文件总数`。
- **A 类抽样逐字节核验**（脚本默认前 80 对）应 100% 一致。
- 若 `kb_null_sha_files > 0` → 回到 Phase 2 补满 KB 再分类。

## Phase 4 — 产出入库/隔离清单（manifest），交用户确认
- 对 C 类：按业务域映射到 KnowsB 顶层域（见 knowsb_domains.md），必要时标注**新增域**。
- 对 A/B 类：目标 = 隔离 HOLD 目录（如 `D:\_recycle_hold\<名>_A1_<日期>\`，**保留相对路径层级**）。
- 代码/工程二进制（`.cs/.dll/.sta/.stu/.ztx/.xsy/.bak/.pv/.tpb` 等）→ 归 `D:\KnowsCode`，不进 KnowsB。
- **目标路径规则（务必遵守，否则执行阶段会塌缩/冲突）**：
  - 镜像源相对路径的全部层级（不要只取二级）。
  - 源 rel 只有一段时：`目标 = 域\<子目录名>\<文件名>`。
  - 同名"文件夹与文件"冲突时，加 `(2)`/`(3)` 后缀去重。
  - 循环变量别用 `d`（会覆盖文件字典 `d`）。
- 写一份**可读清单文档** + 一份 **manifest CSV**（列：源绝对路径, 目标绝对路径, 类别）。
- **停在这，等用户确认。**

## Phase 5 — 执行（同盘改名，可逆，fail-closed）
- `python kb_ingest.py --manifest <清单>.csv`
- 预检失败（源缺失/目标冲突/重复目标）→ **整体中止，0 文件移动**。
- 成功后逐文件三向对账：目标存在 + 源消失 + 大小一致。
- 产出 `move_log.csv`（含每行状态，便于还原）。

## Phase 6 — 收尾
- 告诉用户：**手动删除**对应 HOLD 目录才真正释放空间。
- 入库后 **KB 哈希索引需重扫**（`hash_index.py build --root D:\KnowsB`）——**推送 ima 前必须做**，否则索引与磁盘不一致。
- 记录本次到 memory 日志（新增域、文件数、HOLD 路径）。

---

## 决策速查
| 现象 | 含义 | 动作 |
|---|---|---|
| 含 `.svn` 且体积巨大 | 多为版本控制垃圾 + 工程二进制 | 去重为主，独有文档才入库 |
| A 类占比高 | 源是 KB 的冗余副本堆 | 隔离 A 到 HOLD 即可回收大量空间 |
| C 类占比高 | 源以独有内容为主 | 重点做域归类入库 |
| B 类=0 | 源内无逐字节重复 | 跳过 B |
| 文档去向不明 | 有可能已在 ima | 先追查，勿删残骸 |
